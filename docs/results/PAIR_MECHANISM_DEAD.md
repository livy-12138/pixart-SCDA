# 核心机制失效：pair-aware 绑定偏置在训练后的模型里约等于零

> 本文档回答"导致这种结果的原因是什么"。
> 结论：**论文描述的核心动作——按 object→attribute 边把对象 Token 的
> 图像 Patch 响应路由到对应属性 Token——在代码里存在，在训练好的
> checkpoint 里贡献约 6×10⁻⁴，是数值上的零；并且 `pair` 矩阵不携带
> 任何绑定信息（判别正确/错误配对 8/19，等于随机）。**

---

## 1. 机制本应做什么

前向传播里：

```python
object_repr    = object_pair_proj(text_tokens)      # (B,L,D)
attribute_repr = attribute_pair_proj(text_tokens)
pair = sigmoid(object_repr @ attribute_reprᵀ × scale)      # (B,L,L) 亲和度
pair = pair × object_mask × attribute_mask

object_attention    = softmax(logits 在对象掩码上).mean(heads)   # (B,P,L)
pair_attribute_bias = object_attention @ pair                     # (B,P,L)
logits += softplus(pair_strength) × pair_attribute_bias
```

**预期的语义**：某个 patch 对对象 "book" 关注得多 →
它对 book 所绑定的属性 "blue" 的 logit 被抬高，
使 "blue" 与 "book" 在注意力上强度相当。

---

## 2. 实测：这条链路三层全部失效

用**真实 T5 特征**（从数据集取 `caption_feature`，过 `y_embedder` 后
送入 `SemanticTokenCrossAttention`，与训练/推理完全一致），
在 40 个含 ≥2 条解析边的样本上统计：

| checkpoint | `softplus(pair_strength)` | `pair[正确配对]` | `pair[交叉配对]` | 正确 > 交叉 |
|---|---:|---:|---:|---:|
| token-pair | 0.0493 | **0.014 73** | **0.013 19** | **8 / 19** |
| **TP-SCDA** | 0.0494 | **0.012 38** | **0.010 91** | **8 / 19** |

**三层问题：**

**① `pair` 数值塌陷。** 真实特征下 `sigmoid` 的输入 ≈ **−4.2**，
`pair` 被压到 **0.012~0.015**。
（对照：随机输入时 `pair` 均值 0.497、标准差 0.207、无饱和。
说明这不是参数化本身的问题，而是**训练后的投影对真实文本产出强负点积**。）

**② `pair` 不携带绑定信息。** 正确配对与交叉配对只差 **+0.0015**，
**8/19 判对 = 随机水平**，两个 checkpoint 完全相同。

**③ 再乘 0.049。** `softplus(pair_strength)` 初始 −3.0，
实测 1600 步只从 0.048 53 动到 0.048 48。

**净结果：加到注意力 logits 上的绑定偏置 ≈ 6.1×10⁻⁴（TP-SCDA）/ 7.3×10⁻⁴（token-pair）。**
注意力 logits 本身在 O(1) 量级——**相差约三个数量级**。

---

## 3. 为什么它从未被训练成有用的

- `object_pair_proj` / `attribute_pair_proj` 的**唯一**梯度来源是扩散损失，
  而该梯度必须穿过 `0.049 × 一个约 0.013 的量` → **约 1×10⁻⁴，与噪声不可分**
- 训练目标中**没有任何一项奖励绑定**（`semantic_binding_coef` 默认 0）
- 唯一直接作用于语义分支的项是 `semantic_reg_coef × ‖分支输出‖²`，作用是**把它压小**
- 论文 checkpoint 另有一项 `distill_coef = 0.5`，把输出拉回**未适配的基线**

---

## 4. 这一条解释了此前所有的观测

| 此前观测 | 归因 |
|---|---|
| B1（把 pair 亲和度约束到解析边）是空干预，效应量 0.04%~0.35% | pair 项本身 ≈ 6×10⁻⁴，改准了还是 6×10⁻⁴ |
| 随机向量 ≈ 中性，学到的文本内容显著有害 | 被注入的**只是 role/global 文本摘要**，绑定成分是死的 |
| 注入越强指标越差 | 被强化的只是"不含绑定结构的那部分" |
| TP-SCDA ≈ 冻结基线 | 注入弱到 6×10⁻⁴ 量级，等于没做适配 |
| 门控改造显著变差 | 同上，放大的是没有绑定结构的部分 |
| token-pair 的失败模式是**丢对象**而非属性错绑 | 绑定通路是死的，它做的只是改变文本摘要的注入强度 → 扰乱采样 |

---

## 5. 对论文的直接含义

论文摘要与 3.x 节描述：

> 把对象 Token 的图像 Patch 响应沿合法边路由至对应属性 Token，
> 形成 pair-aware 注意力偏置

**实测：该偏置在训练后的模型中贡献约 6×10⁻⁴，且 `pair` 矩阵对
"正确属性 vs 其他属性"的判别率为 8/19（随机）。**

即：**这一机制在实现中存在，在训练结果中不生效。**
论文不能把绑定效果的缺失归因于"注入过强/过弱"或"门控未激活"——
**根因是这条链路本身没有学到东西，且其增益被设计成 0.049。**

## 6. 可证伪的方式

上述结论基于 19 个有效样本、单一数据集分布。若要复核：

- 换更多样本（当前脚本可扩到数百条）
- 换 prompt 分布（CompBench 提示词而非 COCO caption）
- 直接干预：把 `pair` 强制设为解析边指示矩阵（0/1），
  看输出是否改变——若不变，则确认该通路无贡献

（B1 实质上已做过这个干预的弱化版：把非边的项清零，输出只变 0.04%~0.35%，
与"该通路贡献约 6×10⁻⁴"一致。）
