# 门控改造的实测结论：显著退步

> 结论先行：**把语义分支的门控"打开"（有效强度 0.0164 → 0.063，约 3.9×）
> 会让绑定类指标显著变差。** 这不是噪声——两个已完成类别都通过了配对检验。
> 同时，**论文当前 checkpoint 在绑定类上与冻结基线没有显著差异**。

## 1. 三个模型，同一协议

## 3. 怎么解释

**门控改造本身是成功的**——它证明了门控为什么从来不学习
（sigmoid 饱和 + 学习率不足，见 `results/GATE_OPTIMIZATION.md`），
并让门控真正动了起来（每步学习速度提升约 570×）。

**但它同时证伪了一个隐含假设**：即"门控不学习"是 TP-SCDA 表现不佳的原因。
实测相反——门控一旦被打开，指标**变差**。

训练日志里优化器自己也给出了同样的判断：门控解开冻结后是**向下漂移**的
（0.150 → 0.063），说明在当时的训练目标下，这个分支对降低扩散损失没有贡献，
优化器倾向于关掉它。门控改造强行让它保持开启，代价就体现在绑定指标上。

**有效强度与指标的关系（目前三个点）：**

| 有效强度 | 模型 | 绑定类表现 |
|---:|---|---|
| 0 | frozen | 基线 |
| 0.0164 | tpscda | ≈ 基线（无显著差异） |
| 0.063 | gateopt | **显著低于基线** |

三个点单调向下。这指向一个对论文措辞很重要的结论：
**该语义分支在当前设计下，注入越强越差**；
论文当前 checkpoint 之所以与冻结基线持平，
恰恰是因为它的门控实际上处于近乎关闭的状态（0.0164），
而不是因为分支提供了有效的绑定信号。

## 4. 对 B1 / B2 的含义（重要）

B1 和 B2 都以 gateopt 配置为基座，也就是说**基座本身已经是一个显著退步**。
这带来两个后果，必须如实记录：

1. **B1/B2 应当主要与它们自己的基座（gateopt）比较**，
   才能看出新机制本身是否有效；与 frozen 的直接比较会被基座的退步污染。
2. B1 单独起作用的空间有限：pair bias 的幅值是 `softplus(pair_strength)`，
   训练初始为 `softplus(−3.0) ≈ 0.049`，本身是个小项；
   把它限制到解析边上只是让这个小项**更准**，不会把它变大。
3. **B2 是两者中更值得期待的**：它是唯一直接提供"属性绑定到正确对象"这个
   缺失梯度的机制。门控之前向下漂移，正是因为训练目标里没有这一项。
   B2 检验的假设是：补上这个梯度后，分支能否从"有害"变成"有用"。

## 5. 退步来自哪一侧：global 分支还是 role 分支

> **本节结论已更正。** 加入 tokenpair 这个数据点后，**global 分支的注入量**严格单调地预测三个绑定类指标，而 role 注入量不单调。
> 详见 `results/INJECTION_STRENGTH_LAW.md`。以下保留原始分析以供追溯。

**先更正一个容易犯的错。** 只看门控值会得出错误结论：
门控改造里 global 门是 0.40、role 门只有 0.11~0.13，
看起来像是 global 更强。但前向传播实际注入的是
**整体强度 × 门控值**：

```
x ← x + semantic_gate_scale() · ( g_global · Δ_all + Σ_r g_role_r · Δ_role_r )
```

按这个口径分解两个 checkpoint（脚本 `results/_work/gate_decomposition.py`，
输出 `results/improvement_report/gate_decomposition.csv`；
论文 checkpoint 的强度 0.016 45 与历史审计值 0.016 446 逐位吻合）：

| 通道 | 论文当前 checkpoint | 门控改造 | 倍数 |
|---|---:|---:|---:|
| 整体强度 | 0.016 45 | 0.063 22 | 3.84× |
| **global 实际注入** | 0.016 15 | 0.025 11 | **1.55×** |
| **object 实际注入** | 0.000 29 | 0.008 01 | **27.2×** |
| **attribute 实际注入** | 0.000 29 | 0.006 77 | **23.0×** |
| **relation 实际注入** | 0.000 29 | 0.007 05 | **23.9×** |

**结论：变动的量级差了一个数量级——role 分支涨了 23~27 倍，
global 只涨 1.55 倍。** 退步的主因更可能是 role 分支
（object/attribute/relation 各自的残差，即绑定机制本身），而不是 global 分支。

  可以写出一个探针 checkpoint——把 role 门控置回历史值（0.0179），
  global 门与整体强度保持训练后的值——再走标准协议出图评测。
  脚本已就绪：`results/_work/make_gate_probe_checkpoint.py`。
  代价约 40 分钟（两个绑定类的出图 + 评测），而非 3.6 小时。
  **必须标注为探针**（"门控改造 + 推理时 role 门控置回历史值"），
  不能当作单独训练的变体，也不能与训练得到的 checkpoint 混在同一张表里不加说明。
  prompts / seed / 分辨率 / 采样器 / 步数 / CFG 全部沿用标准协议，只改模型内部一个参数。
- 若探针显示 role 分支确为退步来源，则"让分支真正有益"的方向应是
  **抑制 role 分支、只保留 global 分支**，并把省下的强度让给 B2 的绑定目标。
- 论文 4.3.3 节的措辞需要根据以上结论调整：
  不能写"门控打开后指标提升"，实测是相反方向的显著结果。
