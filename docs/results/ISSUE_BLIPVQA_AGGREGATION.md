# 表 5 的 BLIP-VQA 三列与公开数值不同口径（新发现）

> 这个问题**与掩码问题无关**，是独立的一条。
> 影响论文表 5 的**颜色 / 形状 / 纹理**三列——恰好是 TP-SCDA 的目标指标。

---

## 1. 证据链

### 第一步：主干、权重、生成协议都是对的

用 UniDet / CLIPScore 的四类，本地冻结基线与公开 PixArt-α **几乎重合**：

| 类别 | 评测器 | 本地冻结 | 公开 PixArt-α | 差异 |
|---|---|---:|---:|---:|
| 2D空间 | UniDet | 0.2040 | 0.2064 | −0.0024 |
| 计数 | UniDet | 0.5086 | 0.5058 | +0.0028 |
| 非空间 | CLIPScore | 0.3095 | 0.3197 | −0.0102 |
| 复杂 | 3-in-1 | 0.3314 | 0.3433 | −0.0119 |

差异都在 0.012 以内。**如果本地生成的图质量差，这四类也该低——它们不低。**

### 第二步：只有 BLIP-VQA 的三类对不上

| 类别 | 本地冻结 | 公开 PixArt-α | 差异 |
|---|---:|---:|---:|
| 颜色 | 0.3956 | 0.6690 | **−0.2734** |
| 形状 | 0.4158 | 0.4927 | **−0.0769** |
| 纹理 | 0.4701 | 0.6477 | **−0.1776** |

**结论：图是对的，是 BLIP-VQA 的打分口径不同。**

### 第三步：差异在聚合方式

我们用的是官方仓库 `eval/T2I-CompBench/BLIPvqa_eval/BLIP_vqa.py`。
它按名词短语逐个提问，取 BLIP-VQA 的 "yes" 概率
（`VQA_main` 默认 `inference='vqa_prob'`），然后：

```python
reward_final = reward[:,0]
for i in range(1, np_index):
    reward_final *= reward[:,i]        # ← 连乘
```

**用保留在 `annotation{i}_blip/VQA/result/vqa_result.json` 的逐问题原始答案重算，
把连乘改成均值：**

| 类别 | 官方代码（连乘） | **均值** | 公开 PixArt-α |
|---|---:|---:|---:|
| 颜色 | 0.3956 | **0.6422** | **0.6690** |
| 纹理 | 0.4701 | **0.7119** | **0.6477** |
| 形状 | 0.4158 | 0.6972 | 0.4927 |

**颜色与纹理在均值口径下与公开值接近（差 0.027 / 0.064）；
连乘口径下差 0.27 / 0.18。**

## 2. 尚未解开的部分：形状

形状类在**两种**聚合下都对不上公开值（0.4158 / 0.6972 vs 0.4927），
说明形状列可能还有第三种差异（不同的提示词文件或不同的问题构造）。
**在查清之前，形状列不能断言口径。**

已排除的可能：`np_num` 默认值。官方代码里空问题记 **1.0（中性）**，
所以 `np_num=8` 对只有 2 个名词短语的提示词无害，结果等同 `np_num=2`。

## 3. 对论文的影响

**论文表 5 把本地测得的 TP-SCDA 数值与公开 PixArt-α 数值并列，在那三列上不成立。**
这不是方法的问题，是两套数值不同口径。同样的口径问题也存在于
表 2/3/4 的 CLIPScore 列与任何公开引用的对比中。

**注意：这个问题的表现形式与"方法有没有改进"无关。**
无论用哪种聚合，TP-SCDA 与冻结基线在颜色类上都是：
连乘 0.3956 → 0.3922，均值 0.6422 → 0.6394——**都是约等于零的差**。

## 4. 建议

1. **优先查清形状列**：确认公开 PixArt-α 的形状数值用的是哪个评测器与提示词文件。
2. **不要单方面把聚合改成均值**——要先用官方 T2I-CompBench++ 现行代码复现
   公开值，再决定用哪套。改口径必须有依据，不能为了让数字对上而改。
3. 无论最终选哪套，**论文里必须写明所用评测器的版本与聚合方式**，
   并且在表内不混用两套口径。
4. 原始的逐问题答案已完整保留（每个 np_index 一个 `vqa_result.json`），
   任何口径都可以随时重算，不需要重新生成图片。
