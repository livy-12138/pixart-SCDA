# 优化路线（第二轮）：从"门控改造失败"到可验证的改进方向

> 第一轮（门控改造）的结论是负结果：门控能被激活，但指标显著退步。
> 本文件记录从该负结果中推导出的结构性认识，以及据此设计的后续版本。
> 目标是**在指标上确有提升**，并且每一步都有可提前读出的判据。

---

## 1. 从数据里读出的结构性事实

**事实 A：注入强度与绑定指标单调反向。**

| 语义分支有效强度 | 模型 | 颜色 | 形状 | 纹理 |
|---:|---|---:|---:|---:|
| 0 | 冻结基线 | 0.3956 | 0.4158 | 0.4701 |
| 0.0164 | 论文当前 checkpoint | 0.3922 | 0.4135 | 0.4697 |
| 0.063 | 门控改造 | **0.3616** | **0.3897** | **0.4263** |

后两行相对冻结的配对检验：0.0164 无显著差异；0.063 三类**全部显著退步**。

**事实 B：退步主要来自 role 分支，不是 global 分支。**
按"整体强度 × 门控值"分解（`gate_decomposition.csv`）：global 实际注入 ×1.55，
而 object/attribute/relation 分别 ×27.2 / ×23.0 / ×23.9。

**事实 C：唯一承载"哪个属性属于哪个对象"的通路是 pair bias，
而它被缩放到 ~5×10⁻⁴。**

```
softplus(pair_strength) = softplus(−3.0) = 0.0486
× 语义强度 ~0.09  × 层门控 ~0.10  ≈  5×10⁻⁴
```

attribute 角色分支是把**所有**属性 token 池化后交给每个 patch，**不区分归属**；
object 分支同理。也就是说，架构里"绑定"信息只从 pair bias 一条极细的缝流过。
B1 让这条缝更**准**，但它仍然是细缝——实测效应量只有 0.04%~0.35%，
与训练轨迹同步一起，构成 B1 为空干预的两条独立证据。

**事实 D：优化器一致地想把分支关掉。**
在 gateopt（无 B2）与 B1（无 B2）两次训练中，门控解冻后都**向下漂移**
（0.150 → 0.063 / 0.150 → 0.093）。在扩散 MSE + 残差正则的目标下，
这个分支对降低损失没有贡献。

## 2. 由此推出的改进方向

**方向一：换掉"打开门控"这条已被证伪的路线。**
门控改造的隐含假设是"门控不学习导致效果不好"，
事实 A 证明反了——门控打开后更差。故本方向作废，不再尝试。

**方向二：让 attribute 角色分支变得"对象相关"（B2 承担）。**
B2 的对比损失直接重塑 attention 权重，使"看对象 o 的 patch"对**属于 o 的
属性**权重更高。这样 attribute 角色分支的池化结果就不再是全局属性混合，
而是带着归属信息的 summary。**这是唯一能绕过事实 C 那条缩放链的机制**，
因为它改的是训练目标，不是前向结构。

**方向三：解除配置自身施加的"残疾"。**
第一次 B2 运行从有效强度 **0.150** 开始——正落在已被测得有害的区间里。
任何来自绑定损失的好处，都要先抵消这个由配置自己造成的劣势。
故设计 `b2_neutral`：从历史中性水平 **0.0160** 起步，保留上限 0.3 与
门控增强学习率，让优化器**自由地向上或向下**移动门控。

**判据（可提前读出，不必等评测）：门控漂移的方向。**
- 若 B2 让分支变得有用 → 门控应**向上**漂移
- 若仍然**向下**漂移 → 说明绑定损失也没能让该分支产生价值

这个判据在训练过程中就能从 `training_metrics.csv` 逐 step 读到，
比等 2 小时评测快得多。

## 3. 已排队的版本

| 版本 | 配置 | 相对基座的变化 | 测试什么 |
|---|---|---|---|
| `b2` | `..._b2_bindingloss.py` | gateopt + 绑定损失 | 绑定损失能否改变门控的向下漂移 |
| `b2_neutral` | `..._b2_neutralgate.py` | b2 + 门控初值 −2.88（eff 0.0160） | 去掉配置自身的残疾后，绑定损失能否让分支由害转益 |

队列（GPU 串行，不空闲）：

```
b2 训练 → b2 两套评测 → b2_neutral 训练 → b2_neutral 两套评测 → 打分 + 配对检验
```

脚本：`results/_work/b2_queue.sh`、`results/_work/b2ng_queue.sh`

**B1 已终止**（效应量 0.04%~0.35%，不可能补回基座相对冻结的 0.03 差距），
理由与证据见 `results/b1b2/B1_EFFECT_SIZE.md`。

## 4. 尚未做、待作者决策的

- **推理时 role 门控探针**（约 40 分钟，脚本已就绪
  `results/_work/make_gate_probe_checkpoint.py`）：
  把 role 门控置回历史值、global 与整体强度保持训练后的值，
  直接验证"退步来自 role 分支"（事实 B 的因果检验）。
  **必须标注为探针**，不能与训练得到的 checkpoint 混排。
- **role 抑制型训练版本**：若探针确认 role 是害处来源，
  则"抑制 role、保留 global"是下一个训练版本。
  但需注意：论文当前 checkpoint 本身就是 role≈0.018 / global≈0.98 的配置，
  且它 ≈ 冻结基线，所以**单纯抑制 role 的预期是"回到冻结基线"而非超越**。
  真正的增益仍须来自 B2 这类机制。

## 5. 口径纪律（不变）

- 判断"是否提升"一律用 300 prompt/类、逐提示词配对的 10 000 次 bootstrap 区间
  （`results/_work/compbench_paired_test.py`）；
- 64 提示词代理协议功效不足（39 个 case-seed 判断，全部区间下界 ≤ 0），只作辅助；
- 不改动 prompt 列表 / seed / 分辨率 / 采样器 / 步数 / CFG；
- 不改动 TP-SCDA 核心机制（Token-Pair 机制、object–attribute relation、
  pair compatibility、attention bias、layer/timestep gate、T5 encoder、PixArt backbone）；
- 不做任何蒸馏相关内容；
- 所有改动与结论均写入日志。
