# 提高 TP-SCDA 指标：诊断与方案

日期：2026-09-19　依据：本次全部实测数据

---

## 一、诊断：为什么 TP-SCDA 现在没有效果

CompBench 八项与冻结基线**全部持平**（差 ≤0.01），不是"效果小"，是**方法实际上被关闭了**。

### 1.1 三重乘性门控把信号压成了 3×10⁻⁴

```
有效强度 = semantic_token_gate_max × tanh(语义门控) × sigmoid(层门控)
        =        0.08            ×    0.202    ×     0.018
        =                        3.0 × 10⁻⁴          (object/attribute/relation 三个分支)
```

承载绑定信号的那三个角色分支，实际贡献是**万分之三**。global 分支也只有 0.016。

### 1.2 训练目标里没有任何"绑定"目标

当前损失：
```
L = 扩散 MSE  +  semantic_reg_coef × ‖残差‖²
                        └─ 方向恒定地指向"把注入压小"
```
**没有一项在奖励"属性绑定到正确的对象"。** 方法完全依赖"结构化注入"这一先验：
相信只要把对象 Patch 的响应路由给相连的属性 token，模型就会学对。
这是一个**未经检验的假设**。

### 1.3 偏置不是走解析边，而是走"内容相似度"

论文式(5)描述 B 由解析得到的有向边集 `P_{o,a}` 决定。但 `SemanticTokenCrossAttention`
里实际的 `pair` 是：

```python
pair = sigmoid(object_repr @ attribute_repr.T * scale)   # ← 可学习内容亲和度
pair = pair * object_mask * attribute_mask               # ← 只用 mask，不用解析边 P
```

即：**用"学出来的相似度"代替了"解析出来的依存边"**。P 只出现在基座 cross-attention 的
偏置项里。两者不一致，且内容相似度在训练初期是随机的。

### 1.4 三个已知的次要问题

- 残差被 L2 惩罚持续压小（`semantic_reg_coef` 原为 0.02，是单向压力）
- 门控初始化在 sigmoid 饱和区（已定位，见 GATE_OPTIMIZATION.md）
- 角色门控 3/4 近乎关闭，只有 global 通路开着

## 二、方案（按预期收益 / 成本排序）

### 阶段 A：先把门控真正打开（**正在进行**）

`configs/PixArt_xl2_coco2017_token_pair_gate_opt.py`，已在跑完整 14,786 步：

| 改动 | 作用 |
|---|---|
| 门控初始化 ±4 → ±1 | 进入 sigmoid 线性区，梯度放大 14× |
| 三重压缩 → 单层 `gate_max × sigmoid(w)` | 去掉两层压缩 |
| `gate_max` 0.08 → 0.3，带 warmup | 上限提高 3.75× |
| 门控独立 lr（×100） | 113 个参数不再和 8M 参数共用 lr |
| 冻结 2000 步再解冻 | 避免前期噪声梯度 |
| 正则 0.02 → 5e-5 并退火到 0 | 去掉"压小残差"的单向压力 |

**可行性已验证**：解冻后 1000 步的门控位移 = 原设置全程 14,786 步的 **38.6 倍**，
层间标准差提高 **58 倍**。

**但这是必要条件，不是充分条件。** 门控打开只保证分支"能起作用"，
不保证起了好作用。**必须先评估这个 checkpoint**：
- 若 CompBench 八项或绑定 proxy 有可观提升 → 阶段 A 就够了，剩余是调参
- 若仍然持平 → 问题在机制本身，进入阶段 B

### 阶段 B：机制层面的三条路（若 A 不够）

#### B1. 让偏置真正走解析边 P（**与论文一致，改动小，建议优先**）

把 `pair` 从"内容相似度"改成**解析边 P 与内容相似度的乘积**：

```python
pair = sigmoid(object_repr @ attribute_repr.T * scale) * P_oa   # P_oa 来自解析器
```

理由：解析器已经给出了"哪个形容词修饰哪个名词"的确定信息
（本次实测对象抽取 98–100%、**对齐失败率 0.00%**），
而现在这个信息被浪费了，模型要去从随机初始化的表征里重新学。
**这是最低成本、最可能有效的一改。**

#### B2. 加一个真正的绑定目标函数（**收益上限最高，改动最大**）

当前完全缺失。最小可行的形式是在 `SemanticTokenCrossAttention` 里加一项
**注意力对齐损失**：

```
对每条解析边 (o, a)：让"对象 o 的 Patch 注意力"在属性 token a 处的质量，
显著高于随机属性 token a' 处的质量。
L_bind = -log softmax_o,a / (softmax_o,a + softmax_o,a')
```

依据：SynGen 的核心思想就是对齐名词与修饰词的注意力图；本文的机制目标与之同源，
但训练时没有对应的目标。加上后，绑定能力才有**直接的优化压力**，
而不是指望扩散损失间接地把它学出来。

风险：需要改训练目标（属于方法改动）。建议作为**独立的对照实验**报告，不混入现有消融。

#### B3. 结构性：乘性门控 → 加性 LayerScale

现在角色分支的贡献是 `gate × delta`，gate→0 时梯度也→0（乘性门控的固有病）。
改成标准的 LayerScale 形式 `x = x + λ ⊙ delta`，λ 零初始化、**不经过 sigmoid 压缩**，
是 DiT 里训练最稳的写法。这能同时解决"门控学不动"和"梯度消失"。

### 阶段 C：低成本即时可调项（可在 A 的基础上网格搜索）

| 旋钮 | 现值 | 建议扫描 |
|---|---|---|
| `semantic_token_gate_max` | 0.3 | 0.15 / 0.3 / 0.6 / 1.0 |
| `semantic_reg_coef` | 5e-5 | 0 / 5e-5 / 2e-4 |
| `semantic_gate_lr_mult` | 100 | 30 / 100 / 300 |
| 冻结步数 | 2000 | 1000 / 2000 / 4000 |

## 三、必须先排除的一个混淆：评测协议

**观察：** 与公开 PixArt-α 对比时，用 **UniDet** 的三项几乎完全吻合，
用 **CLIP** 的非空间也吻合，但用 **BLIP-VQA** 的三项系统性偏低：

| 类别 | 评测器 | 本文（冻结 PixArt） | 公开 PixArt-α | 差异 |
|---|---|---:|---:|---:|
| 2D空间 | UniDet | 0.2040 | 0.2064 | −0.002 |
| 计数 | UniDet | 0.5086 | 0.5058 | +0.003 |
| 非空间 | CLIP | 0.3095 | 0.3197 | −0.010 |
| **颜色** | **BLIP-VQA** | **0.3956** | **0.6690** | **−0.273** |
| **形状** | **BLIP-VQA** | **0.4158** | **0.4927** | **−0.077** |
| **纹理** | **BLIP-VQA** | **0.4701** | **0.6477** | **−0.178** |

**同一个模型、同一份 prompt，UniDet/CLIP 三项对得上而 BLIP-VQA 三项对不上**，
说明差异大概率出在 BLIP-VQA 评测路径（权重版本、prompt 版本，或
`np_num=8` 的连乘聚合），而不是模型能力。

**这件事必须先查清**，否则：
- 表5 的颜色/形状/纹理三列会被低估，与公开值不可比
- 任何"提升颜色指标"的努力都会建立在错误的基线上

**建议的核查步骤**（不需要 GPU）：
1. 用 CompBench 官方仓库自带的 `examples/samples/` 4 张示例图跑一遍
   BLIP-VQA，与仓库自带的 `examples/reward/vqa_result.json` 逐值比对
   （**本次已做过，4/4 完全一致 → 评测器代码本身没问题**）
2. 换一个 BLIP-VQA 权重版本重测，看是否系统性变化
3. 确认公开 PixArt-α 的 0.6690 出自哪个 benchmark 版本（原始 T2I-CompBench
   还是 ++），两者 prompt 集与聚合方式可能不同

## 四、建议的执行顺序

```
1. 评估 F5 的门控改造 checkpoint（CompBench 八项 + 绑定 proxy）
   ├─ 有提升 → 阶段 C 调参，固化
   └─ 无提升 → 阶段 B1（走解析边，改动最小）→ 再评估
2. 并行（不需要 GPU）：核查 BLIP-VQA 协议差异（第三节）
3. 若 B1 有效 → 视时间决定是否做 B2（绑定损失）
4. B2/B3 属于方法改动，应作为独立对照实验报告，不混入现有消融
```

## 五、诚实的上限评估

必须说清楚：**即使门控打开、机制修好，TP-SCDA 也不可能大幅超过冻结基线。**

理由：冻结基线已经是**正确的原始 PixArt-α 权重**（本次已逐张量验证 maxdiff=0）。
TP-SCDA 是参数高效适配（可训练参数仅 1.383%），其合理预期是
**在保持整体对齐的前提下，针对性地改善绑定类指标**，而不是全面提升八项。

因此合理的成功标准是：
- 颜色/形状/纹理（绑定类）有**可测量的提升**，且 bootstrap 区间下界 > 0
- 非空间/计数等非绑定类**不退化**

而不是"八项全面超过 PixArt-α 公开值"——那需要的是更强的主干和数据，不是适配方法。
