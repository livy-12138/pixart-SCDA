# TP-SCDA 结构分析：弱项定位与优化方向

> 目的：从实测数据反推结构的薄弱处，给出可执行的改进，
> 并区分**哪些属于允许范围**（新增/配置）、**哪些要动核心机制**（需作者确认）。

## 1. 弱项定位（全部来自实测，不是猜测）

### 弱项 A：计数类显著退步，且**集中在 2 个对象**的提示词上

按解析出的对象数分层（配对 bootstrap，10 000 次）：

| 对象数 | n | 冻结 | TP-SCDA | 差值 | 95% 区间 | 判定 |
|---|---:|---:|---:|---|---|---|
| 1 个 | 73 | 0.6096 | 0.6027 | −0.0068 | [−0.0274, +0.0137] | 无显著差异 |
| **2 个** | **100** | 0.5575 | 0.5225 | **−0.0350** | **[−0.0600, −0.0125]** | **退步（显著）** |
| 3+ 个 | 127 | 0.4121 | 0.4140 | +0.0019 | [−0.0096, +0.0138] | 无显著差异 |

逐条看，退步最大的是 "two sinks and two cups"（1.00→0.25）、
"seven cups"（1.00→0.50）、"six televisions"（1.00→0.50）；
而提升最大的是 "two printers, two cats, three frogs, two birds and three bees"
（0.10→0.40）、"five televisions"（0.50→1.00）。
**退步 23 条 / 提升 13 条 / 持平 264 条。**

## 2. 结构性原因（附代码位置）

### 原因 1：绑定通路被压缩到 ~5×10⁻⁴ ——这是最根本的

前向传播里，pair 偏置进入 logits 时被三级缩放连乘：

```
logits += softplus(pair_strength) * pair_attribute_bias
          └── softplus(−3.0) = 0.0486
x += semantic_gate_scale() * token_delta
          └── 论文 checkpoint ≈ 0.0164
          └── 层门控 sigmoid(layer_gate) ≈ 0.10
```

**净量级 ~5×10⁻⁴。** 实测印证：B1（把 pair 亲和度约束到解析边上，
即使把非边的项全部清零）对输出的改变只有 **0.04%~0.35%**。
`pair_strength` 在训练中几乎不动（0.04853 → 0.04848 / 1600 步），
因为**没有任何一项损失奖励绑定**。
`PixArt.py: ` `logits = logits + torch.nn.functional.softplus(self.pair_strength) * pair_attribute_bias[...]`

### ~~原因 2~~（**已撤回，是错误结论**）

**原文写的**："role 分支把属性全局池化，结构上不区分归属，
所以绑定只能从原因 1 那条细缝流过。"

**这是错的，撤回。** 两点错误：

1. **措辞错误**：那是在 **token 维度**上的加权平均，**每个 patch 各算各的**，
   patch 之间没有任何池化。TP-SCDA 是逐 patch 的交叉注意力。
   真正的"池化"是 Pooled SCDA 那条线（`semantic_adapter` 把角色 token
   压成一个全局向量广播给所有 patch），是另一个消融。

2. **更根本的结论错误**：`weights` **已经包含 pair bias**——

   ```python
   logits = logits + softplus(pair_strength) * pair_attribute_bias
   weights = softmax(logits, dim=-1)      # ← 含 pair 偏置
   role_weights = weights * role
   role_feature = (role_weights @ v) / denom
   ```

   所以 role 分支的加权平均**可以**被 pair bias 推向"该对象绑定的属性"。
   它在结构上没有缺陷。

**更正后的诊断**：影响 role 权重的、唯一带绑定信息的项就是 pair bias，
而它被 `softplus(pair_strength) = softplus(−3.0) ≈ 0.0486` 压制。
**这与原因 1 是同一个瓶颈，不是两个独立问题。**

**连带撤回**：据此提出的"改法 B（把属性池化改成按解析边加权）"建立在
错误前提上，一并撤回。正确做法不是重构聚合方式，
而是**加强那个唯一带绑定信息的项**。

### 原因 3：token-pair 路径**没有时间步调制**，与论文表述不符

论文摘要写"由可学习的层级门控按网络层**与时间步**调节注入强度"。代码里：

```python
token_delta, role_deltas = self.semantic_token_cross_attention(x, y, role_masks, ...)
layer_gates = torch.sigmoid(self.semantic_token_layer_gate[block_index]).view(1, 1, 4, 1)
x = x + self.semantic_gate_scale() * token_delta      # ← 没有 t
```

`t` 只被 pooled 残差路径（`_semantic_residual`）使用。
**token-pair 路径全程等强度注入。**

### 原因 4：解析器把数字同时放进对象与属性掩码

```
"seven cups"  →  对象跨度 = "seven cups"（词 0-1），属性 = 词 0（"seven"）
```
数字词在两边的掩码里都出现，形成的 pair 结构对计数提示词是退化的。
（未证实这与弱项 A 有因果关系，仅作为待查线索记录。）

## 3. 优化方向

### 方向一（**已排队，推理探针**）：限制注入的时间窗

**假设**：绑定在**早期高噪声步**决定，晚期步只做外观细化；
全程注入反而在晚期干扰了计数这类需要"稳住"的属性。

**做法**：不需要重训。给模型加一个默认关闭的时间窗参数，
用同一 checkpoint、同一 prompt/seed/分辨率/采样器/步数/CFG，
只改变分支在哪一段轨迹上开启，对比三个条件：

- 全轨迹（= 现有 `tpscda`）
- 仅早期（t ≥ 500）
- 仅晚期（t < 500）

**验证**（已做）：
- 窗口覆盖全区间时与关闭状态**逐位一致**（max\|Δ\| = 0.000e+00），
  默认路径未被污染；
- 窗口外确实关闭（t=300/50 处输出变化 460%/527%）。

脚本 `results/_work/tsprobe_queue.sh`，评测 color + numeracy 两类。

**若仅早期注入 ≥ 全轨迹**，则方向二成立。

### 方向二（**需作者确认**）：实现论文声称的时间步门控

若方向一为正，就把门控改成真正的时间步函数
（`gate = f(layer, t)`，如 `σ(MLP(t))` 按 role 调制），并重新训练。
**这会改动"layer/timestep gate"，属于任务简报中列明的核心机制**，
所以我只做探针验证，不擅自实现训练版本。

### ~~方向三~~（**已撤回**）

原建议"让 role 分支携带归属信息（按解析边加权池化）"建立在已撤回的原因 2 上，
前提不成立，撤回。见上文更正。

### 方向四（允许范围）：直接把梯度送进那个唯一带绑定信息的项

B2 已经试过并失败——它监督的是 **attention 权重**。但由更正后的诊断可知，
绑定信息本来就只通过 pair bias 影响权重，而 pair bias 幅值被
`softplus(pair_strength)` 压制。在权重上施加对齐损失，
梯度会被 softmax 与后续缩放稀释掉。

**应改为在 role 分支的输出上施加监督**：对接对象 o 的 patch，
要求其 attribute-role 输出更接近 o **绑定的**属性值而非其他属性值。
这样梯度必须穿过 pair bias，才有可能把 `pair_strength` 推大、
把绑定锐化。**这是不改核心机制前提下、唯一直接针对瓶颈的路线。**

---

## 4. 一句话总结

**唯一的根本弱项是"绑定通路被压缩到 ~5×10⁻⁴"（原因 1）**——
影响注意力的、带绑定信息的项只有 pair bias，而它被
`softplus(pair_strength) = 0.0486` 压制，再乘整体强度与层门控。
这不是两个独立问题，是一个。

原因 1 的幅值由 `pair_strength` 与门控共同决定，
**两者都在禁止修改的核心机制里**。在不改核心机制的前提下，
还剩两条路：

- **时间步调制**（原因 3，且论文本就声称有这一功能）——探针已排队；
- **把监督送到 role 分支的输出上**（方向四），使梯度必须穿过 pair bias。

其余方向（改池化结构等）已因前提错误撤回。
