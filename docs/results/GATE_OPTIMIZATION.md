# 可学习层门控为什么没学到东西，以及怎么改

诊断时间：2026-09-18　对象 checkpoint：`output/coco2017_token_pair_learnable_layers/checkpoints/epoch_1_step_14786.pth`

---

## 0. 结论（一句话）

**门控没有学到东西，根因是初始化把参数放进了 sigmoid 的饱和区，
使得「参数能走的距离」比「需要的距离」小了约 20–100 倍。
这与梯度路径、正则系数、蒸馏锚点都无关。**

---

## 1. 现象

从 checkpoint 读出 `semantic_token_layer_gate`（28×4），取 `sigmoid` 后：

| 角色 | 初始化 λ | 训练后 λ | 平均偏移 | 层间标准差 | 最大偏移 |
|---|---:|---:|---:|---:|---:|
| global | 0.982014 | 0.981925 | −0.000089 | 2.9e−05 | 1.6e−04 |
| object | 0.017986 | 0.017898 | −0.000088 | 1.4e−05 | 1.1e−04 |
| attribute | 0.017986 | 0.017885 | −0.000101 | 2.8e−05 | 1.3e−04 |
| relation | 0.017986 | 0.017896 | −0.000090 | 2.4e−05 | 1.2e−04 |

14 786 步之后，28 层的门控彼此几乎完全相同，且都停在初始化值附近。

---

## 2. 量化诊断

### 2.1 梯度确实很小

一次真实前向+反向（`results/_work/gate_diagnosis.py`，fp32，8 条 prompt）：

| 参数组 | 梯度范数 | 参数量 | 每参数梯度 |
|---|---:|---:|---:|
| semantic_token_cross_attention | 1.50e−02 | 7 969 540 | 1.88e−09 |
| semantic_token_gate（标量） | 1.08e−04 | 1 | 1.08e−04 |
| **semantic_token_layer_gate** | **4.04e−05** | 112 | **3.60e−07** |

### 2.2 但真正致命的是 sigmoid 饱和

门控是 `λ_l = σ(w_l)`，因此

```
dλ/dw = λ(1 − λ)
```

| w | λ | dλ/dw |
|---:|---:|---:|
| −4.0 | 0.0180 | **0.0177** |
| −2.0 | 0.1192 | 0.1050 |
| 0.0 | 0.5000 | **0.2500** |
| +4.0 | 0.9820 | 0.0177 |

初始化 `full((28,4), -4.0)` 且第 0 列置 `4.0`，正好把每个参数都放在
**饱和区**：dλ/dw ≈ 0.018，比工作在 λ=0.5 时小 **14 倍**。

### 2.3 关键不等式：门控在数学上走不出饱和区

- 学习率（sqrt 自适应后）：`3.536e-06`
- 训练步数：`14 786`
- 参数**最多**能移动：`14786 × 3.536e-6 ≈ 0.052`
- 实测最大移动：`0.0092`（只用了上限的 18%，因为随机梯度方向不一致）
- 而要从 λ=0.018 走到有意义的 λ（例如 0.27），需要 `Δw ≈ 1.0`

**即：即使每一步的梯度方向完全一致，14 786 步也只够走 0.052 —— 差约 20 倍；
按实测的 0.0092 算，差约 100 倍。**

所以在这个学习率下，**无论训练多久，门控都不可能离开初始化点**。

### 2.4 对照实验（只改一个变量）

`results/_work/gate_init_experiment.py`：同一 checkpoint、同一批数据、同一
AdamW/lr/步数（150 步，lr=3.536e-6，fp32），只改 `semantic_token_layer_gate` 的起点：

| 变体 | \|Δλ\| 最大 | \|Δw\| 最大 |
|---|---:|---:|
| A 当前初始化（w = ±4） | 9.89e−06 | 5.58e−04 |
| B 预热初始化（w = ±1，λ≈0.27/0.73） | **1.06e−04** | 5.39e−04 |
| C 当前初始化，语义 L2 正则系数置 0 | 9.96e−06 | 5.64e−04 |

**B/A = 10.7 倍，而 |Δw| 几乎相同。** 这直接证明：
差异**完全来自 sigmoid 饱和**（同样的参数位移，换来的 λ 位移大 10.7 倍），
**不是梯度变小、也不是正则压制**（C/A = 1.0×）。

## 3. 改进建议（按预期收益排序）

### ★★★ 建议 1：改初始化（一行改动，收益最大，已被上表验证）

`diffusion/model/nets/PixArt.py` 约第 235 行：

```python
# 现在
self.semantic_token_layer_gate = nn.Parameter(torch.full((depth, 4), -4.0))
self.semantic_token_layer_gate.data[:, 0] = 4.0

# 建议
self.semantic_token_layer_gate = nn.Parameter(torch.full((depth, 4), -1.0))
self.semantic_token_layer_gate.data[:, 0] = 1.0
```

λ 从 0.018/0.982 变为 0.269/0.731，落在 sigmoid 的**线性区**。
如果仍然想从保守开始，用 **0 → 用线性斜坡回到 ±4** 的 warm-up，而不是把**参数**钉在饱和点。

### ★★★ 建议 2：去掉双重压缩，或给它退火

当前有效系数是两级压缩相乘：

```
有效强度 = (0.08 · tanh(semantic_token_gate)) × σ(w_l)
         =        0.0164                    ×  0.018        ≈ 3.0e-04   (object/attribute/relation)
```

三个角色分支的实际贡献约 **0.03%**，等于没有。而 `semantic_token_gate_max = 0.08`
只是把输出压到 1.6%；再叠一层 0.018 就彻底消失了。

**建议**：`semantic_token_gate_max` 提到 0.3–1.0，并让它随训练**线性升温**
（0 → target，前 20% 步），或者干脆去掉外层 `tanh`，只保留 `gate_max · σ(w)`。
保守性由下面的蒸馏项负责，不要两个约束叠加。

### ★★ 建议 3：正则与蒸馏退火，而不是恒定

- `semantic_reg_coef = 0.02` 恒定惩罚残差 L2 范数，**方向恒定地指向"减小残差"**。
  实测该项量级 1.7e−02 × 0.02 ≈ 3.5e−04，和 diffusion loss 0.678 比虽然小，
  但它是**单向的持续压力**。
- `distill_coef = 0.5`（每 8 步一次）把学生拉向冻结教师，抑制一切偏离基座的改变。

**建议**：两个系数都做**余弦/线性退火到 0**（例如最后 30% 步）。
先靠它们保证早期稳定，后期放手让门控增长。
注意：150 步的对照实验显示**短期内正则不是主因**（C/A=1.0×），
所以这条的优先级低于建议 1、2 —— 它影响的是**长期**的收敛上限。

### ★★ 建议 4：门控单独的学习率 / 梯度归一化

门控只有 **113 个参数**，却和 800 万参数的投影模块共用 `lr = 3.5e-6`。
建议给 `semantic_token_layer_gate` 与 `semantic_token_gate` 单独设 lr
（例如 100×，约 3.5e-4），或在 optimizer 里对它们做 grad-norm 归一化。

依据：由 2.3 的不等式，要走出饱和区需要 ~20–100 倍的有效步长。

### ★ 建议 5：先冻门控、后解冻（warm-up）

目前门控与投影从第 1 步就一起学。前期投影是随机的，`token_delta` 是噪声，
门控收到的是**噪声梯度**，只会随机游走 —— 这正是实测 `Δw` 只走到理论上限 18% 的原因。

**建议**：前 2 000 步冻结门控（把它们设为常数），让投影先收敛，再解冻。

### ★ 建议 6（最重要的工程改进）：把门控梯度记进日志

现在 `training_metrics.csv` 里只有一个全局 `grad_norm`（0.0005），
**无法判断门控到底有没有在学** —— 这就是这个问题拖到现在才发现的直接原因。

**建议**：在 `train_scripts/train.py` 里对以下参数单独记录 grad norm：

```
semantic_token_layer_gate
semantic_token_gate
semantic_token_cross_attention.out_proj.weight
```

再加一条**健康检查**：若某参数组在 N 步内 `|Δw| < 1e-3 × lr × N`（即连理论上限的
千分之一都没用到），就报警。本次若早有这样的检查，第一次训练就能发现问题。

---

## 4. 建议的验证路径

1. 只改**建议 1**（初始化 ±4 → ±1），跑 2 000 步，看门控是否开始分层（层间标准差是否上升）。
2. 若仍不动，叠加**建议 4**（门控 lr ×100）。
3. 再做**建议 2 + 3**（提高 gate_max + 退火）看绑定指标能否真正提升。
4. 每一步都用 `results/_work/gate_diagnosis.py` 复测梯度量级。

---

## 5. 对论文表述的影响

在修复之前，**4.3.3 节把 binding 由 26/39 提升到 27/39 归因于"层门控用于控制注入
位置与强度"是站不住的**：门控在该 checkpoint 中并未形成层间差异，
其作用退化为一个近乎恒定的保守缩放（global 0.982 / 其余 0.018）。

建议改为如实表述：*门控在本设置下未被有效激活，其作用退化为保守的全局缩放；
我们给出了诊断与改进方向（见附录 X）*。这比一个经不起追问的归因更安全。

## C. 结果：门控确实开始学习了

| 指标 | 旧 run（14 786 步全程） | 新 run（解冻后仅 1 000 步） | 倍数 |
|---|---:|---:|---:|
| 门控相对初始化的位移 `|w-w_init|max` | 9.25e−03 | **3.57e−01** | **38.6×** |
| 层间标准差 `layer_std_max`（λ 空间） | 2.95e−05 | **1.71e−03** | **58.1×** |
| 门控梯度范数 | ~4e−05 | 6–40 | ~10⁵× |
| 标量 token gate | 0.2085 | −0.3211 | 已实际移动 |

**按步数归一后，新设置下门控的有效学习速度提高约 570 倍**
（38.6× 位移 / 1/14.8 的步数）。

轨迹（解冻后）：

```
 step    eff       raw      drift_max   layer_std   gate_grad
 2000  0.15000   0.0000    0.000e+00   0.000e+00   0.000e+00   ← 解冻
 2250  0.14325  -0.0901    9.586e-02   4.136e-04   3.982e+01
 2500  0.13703  -0.1746    1.869e-01   9.704e-04   6.823e+00
 2750  0.13105  -0.2540    2.802e-01   1.432e-03   1.724e+01
```

注意 `eff` 在**下降**（0.150 → 0.126），且正则占比 `semantic_reg_share` 只有约
0.3–1.2% —— 说明这个变化是**扩散目标本身驱动的**，不是正则在推。

## D. 遗留问题

1. **fp16 非有限批次偏多**：3000 步中跳过 **286 次（9.5%）**。守卫工作正常
   （不再崩溃，且已计入 `skipped_batches` 列），但比例偏高。门控放开后激活值变大，
   fp16 更容易溢出。**建议**：改用 bf16，或把 `semantic_token_gate_max` 从 0.3 降到 0.15 再试。
2. 这只是一次 3 000 步的可行性验证，**不是**最终的收敛结果。门控仍在上升期
   （drift 与 layer_std 都在单调增长），需要跑到 14 786 步才能得到可用的 checkpoint。
3. 训练过程中修正的三个自身缺陷（记录在此以便复查）：
   - `model_kwargs` 是**显式白名单**，新配置项必须手动加进去，否则静默使用模型默认值
     （第一次启动时 warmup 因此失效，step 0 就是满强度）；
   - 梯度裁剪会调用 `scaler.unscale_()`，上一批被跳过后再调会抛
     `unscale_() has already been called`；已改为**裁剪前**判定梯度有限性；
   - 门控放开约 10× 后残差范数从 0.27 涨到 7.9（平方后 835×），
     原 `semantic_reg_coef=0.02` 会让惩罚项（1.26）压过扩散损失（0.33）。
     已按比例重标定为 **5e-5**，并把实际占比写进 `semantic_reg_share` 便于复核。
